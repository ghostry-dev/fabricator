# Primitives overview

You reach every primitive through `T`, which `initialize()` returns. There is no other way to name one. See [Public API](/reference/api) for what the package exports.

This page groups the primitives by what you're trying to do. Each one has its own page, and the "All" list in the sidebar has them alphabetically.

Some are left out of the groups on purpose. `compute` is only available inside `.refine(({ compute }) => ...)` (see [Objects](/guides/objects#computed-fields)). `self` is only the placeholder `T.recursive(body)` passes to `body`; there is no `T.self` (see [`T.recursive`](/reference/primitives/recursive)).

## Things that trip people up early

- **[`T.string`](/reference/primitives/string) and [`T.bigint`](/reference/primitives/bigint) can't be used bare.** There's no natural default range for either, so `T.string` on its own fails when fabricated. Call `.whereby({ length })` (or `.as(...)`) first.
- **Weights don't need to add up to anything.** This applies to [`T.enum`](/reference/primitives/enum), [`T.choice`](/reference/primitives/choice), and `.weighted()` on the [absence](#absence) primitives. Each weight is divided by the total of all weights. A weight of `0` turns that outcome off, and it throws if every weight is `0`. Negative weights, `NaN`, and `Infinity` are invalid.

## Scalars

A single value of one JavaScript type. Most are drawn at random; [`T.symbol`](/reference/primitives/symbol) creates a new symbol each time.

- [`T.string`](/reference/primitives/string): can't be used bare; needs `.whereby({ length })`
- [`T.number`](/reference/primitives/number): unbounded when bare, or `.whereby({ min, max })`; `.integer` for whole numbers
- [`T.bigint`](/reference/primitives/bigint): can't be used bare, for the same reason as `T.string`
- [`T.boolean`](/reference/primitives/boolean): 50/50, or `.weighted({ true, false })`
- [`T.date`](/reference/primitives/date): dates within a range, plus `.past` and `.future`
- [`T.symbol`](/reference/primitives/symbol): `Symbol()`, or `.keyed(description)`

## Literals and choices

Ways to get a value from a fixed set. They differ in whether the value is fixed or drawn, and whether the members are values or schemas.

|                                            | Picks a                    | Members are     | Bare form                   |
| ------------------------------------------ | -------------------------- | --------------- | --------------------------- |
| [`T.always`](/reference/primitives/always) | —                          | any fixed value | yes                         |
| [`T.enum`](/reference/primitives/enum)     | value                      | any value       | no — `.uniform`/`.weighted` |
| [`T.choice`](/reference/primitives/choice) | schema, then fabricates it | any schema      | no — `.uniform`/`.weighted` |

## Absence

Ways for a value to be _not quite there_. They are not interchangeable, and most confusion comes from answering the wrong one of these questions:

- **Is the key on the object at all?** This is about the enclosing `T.object`, and means nothing outside one.
- **Once the key is there, is the value `null`, `undefined`, or something else?** This is about the value itself, so it works anywhere a schema does: a top-level Fabricator, an array element, or an object field.

| I want...                                                                      | Use                                                         | Key present? | Value when "absent"                  | Object-only? |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------- | ------------ | ------------------------------------ | ------------ |
| A value that is always exactly `null`                                          | [`T.null`](/reference/primitives/null)                      | —            | `null`                               | no           |
| A value that is always exactly `undefined`                                     | [`T.undefined`](/reference/primitives/undefined)            | —            | `undefined`                          | no           |
| A field that's always present, but the value might be `undefined`              | [`T.undefinable(inner)`](/reference/primitives/undefinable) | always       | `undefined`                          | no           |
| A field that's always present, but the value might be `null`                   | [`T.nullable(inner)`](/reference/primitives/nullable)       | always       | `null`                               | no           |
| A field that's always present, value might be `null` _or_ `undefined`          | [`T.nullish(inner)`](/reference/primitives/nullish)         | always       | `null` or `undefined`                | no           |
| A field that's sometimes missing from the object entirely                      | [`T.omittable(inner)`](/reference/primitives/omittable)     | sometimes    | _(key doesn't exist)_                | yes          |
| A field that might be missing, present-as-`undefined`, or present with a value | [`T.optional(inner)`](/reference/primitives/optional)       | sometimes    | _(key doesn't exist)_ or `undefined` | yes          |

[`T.omittable`](/reference/primitives/omittable) and [`T.optional`](/reference/primitives/optional) only make sense as fields inside `T.object(...)`. [`T.nullable`](/reference/primitives/nullable), [`T.nullish`](/reference/primitives/nullish), and [`T.undefinable`](/reference/primitives/undefinable) are ordinary values you can use anywhere.

When a field comes out omitted, `null`, or `undefined`, its inner schema isn't fabricated at all. Each field has its own stream, so skipping that draw only affects the same field's next call, never another field. See [Reproducibility](/guides/reproducibility#which-field-gets-which-randomness).

## Collections

Ways to fabricate more than one value. They differ in whether every item has the same shape, and whether items are found by index or by key.

|                                            | Positions   | Shape                  | Count                |
| ------------------------------------------ | ----------- | ---------------------- | -------------------- |
| [`T.array`](/reference/primitives/array)   | index       | same for every element | random               |
| [`T.tuple`](/reference/primitives/tuple)   | index       | separate for each slot | fixed                |
| [`T.record`](/reference/primitives/record) | key (drawn) | same for every value   | random, may collapse |

## Structures

- [`T.object`](/reference/primitives/object): what most schemas are built inside. See [Objects](/guides/objects) for details.
- [`T.pick`](/reference/primitives/pick) and [`T.omit`](/reference/primitives/omit): a copy of an object schema with only some of its fields.
- [`T.recursive`](/reference/primitives/recursive): a schema that refers to itself, for trees, linked structures, or a generic JSON value.
- [`T.derive`](/reference/primitives/derive): a value computed from other schemas' fabricated values, without a throwaway object.

## Escape hatch

- [`T.opaque`](/reference/primitives/opaque): a `Map`, a `Set`, a `URL`, a class instance, or anything else fabricator has no primitive for.

Most other primitives also have `.as(produce)`, which replaces how an existing kind is generated with your own function. Use `.as()` to change a kind that exists, and `T.opaque` when there's no kind to start from. See [`T.opaque`](/reference/primitives/opaque) for the difference, and [Custom types](/guides/custom-types) for using `.as()` with a data library.
