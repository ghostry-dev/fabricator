# Installation

Fabricator is ESM only and has no runtime dependencies.

:::code-group

```bash [bun]
bun add @ghostry/fabricator
```

```bash [npm]
npm install @ghostry/fabricator
```

:::

## Requirements

- A runtime that supports ES modules: Bun, Node, Deno, or a bundler.
- TypeScript is not required, but it is strongly recommended. Fabricator is built for it, and the type of every fabricated value is inferred from its schema.

## Optional: a dynamic data library

By default, fabricator generates arbitrary (fuzzing) values, not realistic ones. `T.string.whereby({ length: { max: 20 } })` gives you a random string, not a name. For data that looks real, add the Faker extension:

:::code-group

```bash [bun]
bun add @ghostry/fabricator-extension-faker-v10 @faker-js/faker
```

```bash [npm]
npm install @ghostry/fabricator-extension-faker-v10 @faker-js/faker
```

:::

```ts
import { en } from "@faker-js/faker";
import { initialize, registry } from "@ghostry/fabricator";
import { fakerExtension } from "@ghostry/fabricator-extension-faker-v10";

const { T } = initialize({
  types: registry.extend(fakerExtension({ locale: en })),
});

const schema = T.faker.person.fullName();
// a T.string that fabricates faker values
```

Faker draws from fabricator's randomness, so these fields replay like any other. See [the Faker guide](/guides/faker) for everything it provides.

You can also call any data library yourself with `.as(...)` or `T.opaque`. See [`T.opaque`](/reference/primitives/opaque), including how to keep those fields reproducible.

## Optional: schema adaptation for runtime validation

Fabricator doesn't validate values against a schema. To use the same shape as a validator too, add the TypeBox adapter:

:::code-group

```bash [bun]
bun add @ghostry/fabricator-adapter-typebox-v0 @sinclair/typebox
```

```bash [npm]
npm install @ghostry/fabricator-adapter-typebox-v0 @sinclair/typebox
```

:::

```ts
import { toTypeBox } from "@ghostry/fabricator-adapter-typebox-v0";

const TProduct = toTypeBox(ProductSchema);
```

It targets `@sinclair/typebox` 0.34.x, which is what the `-v0` means. See [the TypeBox guide](/guides/typebox) for how each primitive maps by default and how to override that per schema.

## Optional: a test harness

`@ghostry/harness` wraps your test runner's `describe`/`it` so each test draws data based on its own name. That data is reproducible and doesn't depend on which other tests ran:

:::code-group

```bash [bun]
bun add -d @ghostry/harness
```

```bash [npm]
npm install --save-dev @ghostry/harness
```

:::

See [the Harness guide](/guides/harness) for setup.

## Optional: extern blocks

`@ghostry/extern-extension-fabricator-v0` lets a `typed` extern block that uses a fabricator schema mock itself. Inside a testing block, it fabricates from its schema, so you don't have to write a mock.

:::code-group

```bash [bun]
bun add @ghostry/extern @ghostry/extern-extension-fabricator-v0
```

```bash [npm]
npm install @ghostry/extern @ghostry/extern-extension-fabricator-v0
```

:::

See [the Extern guide](/guides/extern) for the setup.

## Optional: a census of real data

A schema's ranges, weights, and distributions are usually guesses. `@ghostry/fabricator-census` reads a sample of real data and suggests them. It can also build the PostgreSQL queries to collect that sample:

:::code-group

```bash [bun]
bun add -d @ghostry/fabricator-census
```

```bash [npm]
npm install --save-dev @ghostry/fabricator-census
```

:::

```ts
import { census, report } from "@ghostry/fabricator-census";

console.log(report(census.from(rows)));
```

See [the Census guide](/guides/census) for how to read the suggestions and sample a table.
